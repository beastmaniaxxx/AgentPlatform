## 1. プロジェクト概要

### 1.1 目的

ローカル環境で完結する**完全セルフホスト型のマルチモーダルAIエージェント**を構築する。テキスト・画像の入出力を統合的に扱い、Web検索・逆画像検索・ローカルストレージ内検索・画像生成・動画生成を一つのチャットUIから自然言語で操作できる環境を実現する。

### 1.2 開発の背景

クラウド型AIサービスはプライバシー・データ主権・継続的なコストの面で個人利用において制約がある。本プロジェクトはオープンソースのコンポーネントを組み合わせ、外部API依存を最小限に抑えつつ、必要な機能だけ外部API（SerpAPI、Instagram Graph API）で補完する設計とする。

### 1.3 開発スコープ

| 区分     | 内容                                                                  |
| -------- | --------------------------------------------------------------------- |
| 対象     | 個人開発・個人利用を前提とした単一ホストでの動作                      |
| 対象外   | マルチテナント対応、SLA保証、商用展開、本番運用レベルの監視・冗長化   |

### 2.2 機能詳細

#### 2.2.1 Web検索（ワード検索）

- **目的**：LLMの知識カットオフを補い、最新情報を回答に組み込む
- **入力**：自然言語によるテキストクエリ
- **処理**：
  1. ユーザー入力をOpen WebUIで受け取り、Difyへ転送
  2. DifyワークフローからSearXNGを呼び出し、複数エンジン（Google・Bing・DuckDuckGo・Brave等）の結果を匿名で取得
  3. ローカルLLMが結果を要約・整形してOpen WebUIへ返却
- **出力**：要約結果＋引用元URL

#### 2.2.2 Web検索（画像検索）

- **目的**：キーワードに基づくWeb上の画像取得
- **入力**：自然言語によるテキストクエリ
- **処理**：
  1. SearXNGの画像カテゴリ（`!images`）に対してクエリ送信
  2. 取得した画像URLリストをDifyワークフローで整形
- **出力**：チャット内にMarkdown形式（`![](url)`）で画像を埋め込み表示
- **対応エンジン**：Google Images、Bing Images、DuckDuckGo Images、Yandex Images（手動有効化）

#### 2.2.3 Web検索（逆画像検索）

- **目的**：手元の画像と類似する画像をWeb上から探す
- **入力**：Open WebUIへアップロードする画像ファイル（base64）
- **処理**：
  1. Open WebUIにアップロードされた画像をPipelineスクリプトで受け取る
  2. base64を一時画像ホスティング（imgpush）へPOSTし、公開URLを取得
  3. DifyのHTTPノードから当該URLをSerpAPI（`engine=google_reverse_image` または `engine=google_lens`）へ送信
  4. 類似画像URLリスト・出典サイトをLLMで要約
- **出力**：類似画像のサムネイル＋出典サイト一覧

#### 2.2.4 Web検索（Instagram画像検索）

- **目的**：特定ハッシュタグの投稿画像を取得
- **入力**：ハッシュタグまたは自然言語入力（LLMでハッシュタグを抽出）
- **処理**：
  1. Instagram Graph APIの `/ig_hashtag_search` でハッシュタグIDを取得
  2. `/{hashtag-id}/recent_media` で投稿一覧を取得
  3. キャプション・permalinkをLLMで整形
- **出力**：投稿一覧（permalink・キャプション要約）
- **既知の制約**：
  - ビジネス／クリエイターアカウントが必要
  - 個人アカウントへのアクセス不可
  - 1週間あたり30ユニークハッシュタグまで
  - ハッシュタグ検索で他者投稿の `media_url`（画像URL）は取得不可
  - 取得可能フィールドは `id`・`media_type`・`caption`・`permalink` 等に限定

#### 2.2.5 ストレージ内画像検索（マルチモーダルRAG）

- **目的**：事前にナレッジベース登録した画像から類似画像を検索
- **入力**：テキストまたは画像（Markdownリンク経由、JPG/PNG/GIF、最大2MB）
- **処理**：
  1. Dify v1.11.0以降のマルチモーダル埋め込みモデルでベクトル化
  2. テキスト→画像・画像→テキスト・画像→画像のクロスモーダル検索
  3. マルチモーダルRerankingで関連度の高い結果を上位提示
- **出力**：類似画像＋関連テキスト
- **位置づけ**：逆画像検索のフォールバック先（自鯖内に存在するか先にチェック、なければWeb検索）

#### 2.2.6 画像生成（ComfyUI）

- **目的**：テキスト・ポーズ参照画像からの画像生成、または参照画像＋指示による画像編集（I2I）
- **入力**：自然言語プロンプト（必要に応じてポーズ参照画像、または参照画像＋編集指示）
- **処理**：
  1. LLMがプロンプト／編集指示を翻訳・拡張・整形
  2. DifyのComfyUIプラグインがワークフロー（API Format: text-to-image / ControlNet / img2img）を呼び出し
  3. 必要に応じてControlNetでポーズ制御
- **出力**：生成／編集画像（URL or base64）をOpen WebUIにMarkdown形式で返却

#### 2.2.7 動画生成（ComfyUI）

- **目的**：テキストから短尺動画を生成
- **入力**：自然言語プロンプト
- **処理**：ComfyUIの動画生成ワークフロー（AnimateDiff・WAN系等）を呼び出し
- **出力**：生成動画ファイル
- **検討事項**：動画生成はVRAM・処理時間のリクワイアメントが大きく、ハードウェアによっては実行不可

### 2.3 LLM要件

| 項目           | 内容                                                         |
| -------------- | ------------------------------------------------------------ |
| 利用モデル①    | Qwen 3.6（Vision Encoder搭載）                               |
| 利用モデル②    | Gemma 4（Vision Encoder搭載）                                |

## 3. 非機能要件

### 3.1 システム構成

| 機能                   | サービス名 | バージョン | 備考                       |
| ---------------------- | ---------- | ---------- | -------------------------- |
| OS                     | Windows 11 | 24H2以降   | WSL2上でDocker動作         |
| 仮想コンテナ           | Docker     | 最新       | Docker Compose使用         |
| AIチャットサーバ       | Open WebUI | 最新       | フロントエンド／入力部     |
| ローカルLLMサーバ      | Ollama     | 最新       | OpenAI互換API公開          |
| メタ検索エンジンサーバ | SearXNG    | 最新       | JSON出力有効化必須         |
| 検索API                | SerpAPI    | -          | クラウドサービス（外部）   |
| AIエージェントサーバ   | Dify       | v1.11以降  | マルチモーダルRAG対応版    |
| 画像生成サーバ         | ComfyUI    | 最新       | Dev Mode有効化必須         |
| 一時画像ホスティング   | imgpush    | 最新       | 逆画像検索用URL化に使用    |
| ローカルLLMモデル①     | Qwen 3.6   | -          | Vision Encoder搭載モデル   |
| ローカルLLMモデル②     | Gemma 4    | -          | Vision Encoder搭載モデル   |

### 3.2 ハードウェア要件

| 項目     | 最低                | 推奨                          |
| -------- | ------------------- | ----------------------------- |
| CPU      | 8コア               | 12コア以上                    |
| RAM      | 32GB                | 64GB以上                      |
| GPU      | NVIDIA RTX 3060 12GB | NVIDIA RTX 4090 24GB         |
| VRAM     | 12GB                | 24GB以上（動画生成考慮）      |
| ストレージ | NVMe 500GB          | NVMe 2TB以上（モデル＋画像）  |

### 3.3 ネットワーク要件

- 全コンポーネントは同一Docker network上に配置し、コンテナ名でURL解決する
- ホスト→コンテナ通信が必要な箇所は `host.docker.internal` を利用
- 外部接続はSearXNGの検索プロバイダ・SerpAPI・Instagram Graph APIへのアウトバウンドのみ

### 3.4 セキュリティ要件

| 項目           | 内容                                                             |
| -------------- | ---------------------------------------------------------------- |
| API キー管理   | `.env` ファイルで管理、Gitリポジトリには含めない                 |
| 認証           | Open WebUI標準のローカルユーザー認証                             |
| 外部送信       | 逆画像検索時のみ画像URLがSerpAPIへ送信される（要ユーザー認識）   |
| Instagram連携  | 個人アカウントは利用不可、ビジネスアカウント運用時は規約遵守     |

### 3.5 プライバシー要件

- テキスト検索・キーワード画像検索はSearXNG経由で完全匿名
- 逆画像検索は外部API利用のため、画像URLが第三者サーバーへ送信される旨をUI上で通知
- LLM推論はすべてローカル（Ollama）で実行、外部送信なし

### 3.6 コスト要件

| 項目             | 想定コスト               | 備考                              |
| ---------------- | ------------------------ | --------------------------------- |
| ソフトウェア     | 0円                      | すべてOSSのセルフホスト          |
| SerpAPI          | $0〜$75/月               | 月100検索まで無料、以降有料プラン |
| Instagram API    | 0円                      | Meta開発者登録要、商用は要確認    |
| インフラ         | 既存PC利用前提           | クラウド利用時は別途              |
| 電気代           | -                        | GPU稼働時間に依存                 |

### 3.7 可用性・運用要件

- 個人開発のため99.9%等のSLAは設定しない
- 自動起動：Docker Composeの `restart: unless-stopped` で対応
- バックアップ：Difyのナレッジベース・SearXNG設定・ComfyUIワークフローを定期的に外部ストレージへ保存
- ログ：各コンテナ標準ログのみ、集約基盤は構築しない

## 4. システムアーキテクチャ概要

### 4.1 全体フロー

```
[ユーザー]
    ↓ プロンプト入力／画像アップロード
[Open WebUI]
    ↓ Pipeline（Python）：base64→URL変換等の前処理
[Dify ワークフロー]
    ├─ 分岐①：テキスト検索 → SearXNG → Ollama要約
    ├─ 分岐②：画像検索 → SearXNG（!images）→ Markdown整形
    ├─ 分岐③：逆画像検索 → imgpush → SerpAPI → Ollama要約
    ├─ 分岐④：Instagram → Graph API → Ollama要約
    ├─ 分岐⑤：ストレージ内検索 → マルチモーダルRAG
    ├─ 分岐⑥：画像生成 → Ollama（プロンプト拡張）→ ComfyUI
    └─ 分岐⑦：動画生成 → Ollama（プロンプト拡張）→ ComfyUI
    ↓ 結果を統合
[Open WebUI]
    ↓ Markdown形式で表示
[ユーザー]
```

### 4.2 コンポーネント間連携

| 連携元      | 連携先       | プロトコル                       | 備考                  |
| ----------- | ------------ | -------------------------------- | --------------------- |
| Open WebUI  | Dify         | HTTP（OpenAI互換）＋Pipeline中継 | コード記述要箇所      |
| Dify        | Ollama       | HTTP（Ollama API）               | GUIで設定             |
| Dify        | SearXNG      | HTTP（JSON）                     | プラグイン            |
| Dify        | ComfyUI      | HTTP（API Format）               | プラグイン            |
| Dify        | SerpAPI      | HTTPS                            | HTTPノード            |
| Dify        | Instagram    | HTTPS（Graph API）               | HTTPノード            |
| Pipeline    | imgpush      | HTTP                             | base64→URL変換用      |

## 6. リスクと前提

### 6.1 技術リスク

| リスク                                              | 影響度 | 対策                                        |
| --------------------------------------------------- | ------ | ------------------------------------------- |
| Qwen 3.6 / Gemma 4が予定通りリリースされない        | 中     | 既存のQwen3 / Gemma3で代替                  |
| Instagram Graph APIの仕様変更                       | 高     | 機能限定／代替手段（外部スクレイパー）検討  |
| SerpAPI料金プラン変更                               | 中     | TinEye経由のSearXNG運用に切り替え           |
| OpenWebUI ↔ Dify間のファイル受け渡し改善待ち        | 中     | 当面はPipelineスクリプトで対応              |
| ComfyUIのワークフロー互換性                         | 中     | API Format形式で固定保存                    |
| GPUリソース不足（特に動画生成）                     | 高     | 動画機能はオプション扱い、画像生成優先      |

### 6.2 前提条件

- Windows 11 + WSL2環境でDockerが動作すること
- NVIDIA GPU（CUDA対応）が利用可能であること
- インターネット接続（モデルダウンロード・外部API利用に必要）
- Meta開発者アカウント（Instagram連携利用時）
- SerpAPIアカウント（逆画像検索利用時）

## 7. 今後の検討事項

- 画像生成と逆画像検索を組み合わせた「参照画像から類似画像生成」フロー
- 生成済み画像のナレッジベース自動登録による検索資産化
- 音声入出力（STT/TTS）の追加検討
- Dify以外のオーケストレーター（n8n等）との比較検証
- Open WebUIのCanvas／Artifacts機能との連携

## 8. 用語集

| 用語              | 説明                                                        |
| ----------------- | ----------------------------------------------------------- |
| RAG               | Retrieval-Augmented Generation（検索拡張生成）              |
| マルチモーダルRAG | テキスト・画像など複数モダリティを統合的に扱うRAG           |

| Pipeline          | Open WebUIの拡張Pythonスクリプト機構                        |
